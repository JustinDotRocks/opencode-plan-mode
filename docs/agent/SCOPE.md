# SCOPE.md
Never touch unrelated logic unless required.

In scope: only files/symbols needed for the card’s stated goal; tests/docs that prove it; shared utilities only if the card cannot land without them (call out in the plan).

Out of scope: refactors, renames, drive-by cleanups, unrelated bugfixes, formatting-only churn, features not on the card.

If blocked: ask or split the card — do not expand scope to unblock yourself.
